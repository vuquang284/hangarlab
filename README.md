# HangarLab

Size a multirotor, fixed-wing or VTOL drone, check its power and radio links, and compare the plan with real flight logs. Everything runs in the browser; designs are saved in the browser's local storage, with export and backup built in.

## What it does

- **Performance**: pick the configuration, motor, prop, battery and payload; hover time, range, top speed, wind limit, current draw and checks update as you type.
- **Compare**: designs side by side.
- **Parts & Weight**: every part with weight, cost, balance, supply rail and radio band.
- **Electrical, Radio Link, 3D Printing**: regulators and wiring, link budgets, filament choice and printed-part mass.
- **Parts Library**: the motors, props, packs and parts every design draws from, with bench thrust tests and APC prop data.
- **Flight Logs**: open an ArduPilot `.bin` or `.log` and compare it with the design.

## Running it

The app is static files with no dependencies to install.

- **Single file:** open `hangarlab/HangarLab.html` in a browser. It is self-contained; only the 3D views, the log map and spreadsheet or zip imports fetch a library from a CDN when first used.
- **From the sources:** serve the `hangarlab/` folder and open it, for example:

  ```bash
  python -m http.server 8000 --directory hangarlab
  ```

  then go to <http://localhost:8000>.

## Development

Requires Node.js (any current LTS). Run these from `hangarlab/`:

| Command | What it does |
| --- | --- |
| `node test.js` | Self-check of the flight model, battery maths, log parsing and imports. |
| `node build.js` | Rebuilds `HangarLab.html` from `index.html` and the scripts. Run it and commit the result after any source change; CI fails if it is out of date. |
| `node make_defaults.js <backup.json> [--designs]` | Makes an exported workspace backup the built-in library (and optionally example designs). `--reset` goes back to the library in `data.js`. |
| `python make_template.py` | Rebuilds the Excel import template and `template.js` (needs `openpyxl`). |

### Files

| File | Contents |
| --- | --- |
| `index.html` | Page layout and styles. |
| `engine.js` | Flight, battery, electrical and RF model, plus log parsing (`window.UAS`). No DOM access, so `test.js` runs it in Node. |
| `apc.js` | APC propeller performance data. |
| `data.js`, `library.js` | Built-in parts library and example designs; `library.js` overrides it when generated by `make_defaults.js`. |
| `template.js` | The Excel template, embedded for download. |
| `uPlot.iife.min.js` | [uPlot](https://github.com/leeoniya/uPlot) 1.6.30 (MIT), for the charts. |
| `app-core.js` | UI state, storage, units, form builders, charts, header. |
| `app-design.js` | Performance tab. |
| `app-parts.js` | Parts & Weight, Electrical and Radio Link tabs. |
| `app-print.js` | 3D Printing tab and STL preview. |
| `app-library.js` | Parts Library tab and imports. |
| `app-logs.js` | Flight Logs tab. |
| `app-export.js` | Dialogs, export and Settings. |
| `app-main.js` | Quick start, Compare tab, events and start-up. |

The `app-*.js` files are plain scripts that share one global scope, so their load order matters. It is listed in both `index.html` and `build.js`, and `app-main.js` must come last.
